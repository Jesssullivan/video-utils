## Change

- `scripts/annotation_v2.py`
  - New kinds `onset` (point only) and `onset_segment` (known span only). Both require an operator basis. The 11
    issue kinds keep their behaviour.
  - `import-labels` operation: reads a `start<TAB>end<TAB>text` label-track export. Times are relative to a run
    WAV (`source.wav`, `denoised.wav` or `cleaned.wav`), which must match its manifest hash. Each time becomes
    `audio_start_seconds` plus the label seconds. Every row is validated before the first write. Keys derive
    from the label-file hash, so a second import replays.
- `scripts/onset_benchmark.py` (new)
  - `ordered_pairs`: one-to-one matching, maximum count then minimum total offset. It is the same programme as
    `event_metrics_v2` in `scripts/benchmark.py`, and a test checks that they agree on 100 random cases.
  - `onset_label_benchmark`: P/R/F1 at 10, 25 and 50 ms, per detector kind and time axis. Subsets: all labels and
    confirmed-only.
    - Precision is computed only inside `onset_segment` spans. Without segments the scorer reports recall only.
    - The scorer abstains below 10 scored labels.
    - Contested-match counts show ambiguity. The median offset is reported and never subtracted.
  - CLI: writes a fresh receipt that holds hashes only and no paths.
  - `scripts/benchmark.py` itself is unchanged. The first draft added the scorer there and broke 6 holdout tests:

## Findings

- The browser review UI has no waveform and seeks in 1 s steps. A quick mark taken during playback carries the
  operator's reaction delay, often 150–250 ms. That is outside every tolerance, so the guide recommends labelling
  onsets in an audio editor and importing them. Boundary marks at ±100 ms can use the browser if playback is paused.
- The store cap is 200 records. At technical tempos a fully labelled 20–30 s stretch can exceed it. The guide asks
  for fully labelled segments of 3–8 s inside the stretch.
- Follow-ups:
  - The scorer has no typed MCP hook. Adding one needs a tool admission and a descriptor freeze, both owned by
    root.
  - The D6 rows in `docs/spec/PROJECT.md` are root's to update after the session.
