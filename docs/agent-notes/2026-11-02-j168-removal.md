# J168 removal, narrate half

November 2, 2026, TIN-7125. Direction: J168 (`9738d494`) and SPR-339 (`1786d297`). Receipts cite
R-HOOK-CONVERGENCE-20261004.

J168 removes the `ip_private` and BS-21 code refusals for go-live, and the November 30, 2026 audit revisits them. The
Cade half and the audit list are in `docs/J168_REMOVALS.md` of xoxd-ai/cade.

| Check | Site | Effect |
| --- | --- | --- |
| `ip_private` | `private_terms.required`, `read_denylist` | `ip_private` alone needs no denylist and no digest. A bound `denylist_sha256` or a pin still needs the file |
| `ip_private` | `private_terms.NEEDS` | `ip_private` needs no number or geometry entry |
| `ip_private` | `private_terms.scan`, `MATCHED` | Number and geometry entries parse and do not match |
| BS-21 | `private_terms.scan`, `SCRIPT_MATCHES` | The `script` class does not refuse, on any bundle |
| BS-21 | `subject.subject` | `nv subject` stops refusing `shown_text_unread` except on a `never_name` marker, and prints `shown_unread` |

J168's flag (`9738d494`) says to remove only the named checks, and that the removal lifts neither SPR-102 nor anything
the law requires. Nothing here touches SPR-102, no `ip_private` reader reaches an export or a hosted engine, and SPR-339
adds no brand-only refusal. Legal acts stay with Jess (TIN-2345).

`never_name` keeps its denylist, its name entry and its name match. It does not keep the `script` class, which caught
letters outside the `CONFUSABLES` floor. So a listed name spelled with a small capital, an Armenian letter or a Lisu
letter no longer refuses until the audit. `2201b219` lists the script class, so the removal is ruled, and
`test_a_listed_name_outside_the_confusables_floor_no_longer_refuses` pins the gap. Whether `never_name` should keep
`script_hit` is open for Jess. `redact` still withholds a detail that holds a foreign letter, because it refuses
nothing. Restoring the rules takes `MATCHED = CLASSES`, `SCRIPT_MATCHES = True`, the `NEEDS` entry and the two
conditions, or one revert.

Jess's decision `654c5b08` keeps `shown-text-unread` on `never_name`, which narrows the scope note `2201b219` there.
BIZ-17 coverage stays, and elsewhere the removal stands. Each reader refuses where it can see the flag:

| Path | Who sees `never_name` | Who refuses a shown asset no check read |
| --- | --- | --- |
| `nv subject`, job with a guarded intake's marker | the marker, a new field that travels with the records. A marker older than the field reads as `never_name` | `nv subject` |
| `nv subject`, job with no marker | nobody here. The packet record holds the flag | nobody. It prints `shown_unread` |
| `client-video-narrated-render` | `subjectOf` reads the packet record | `subjectOf`, on `shown_unread` (cade#246). `nv subject` exiting non-zero was this path's only signal, so removing it without this field would have left no refusal |
| `cade-hardware-handoff` | the packet record | its own `shown-text-unread`, narrowed on cade#267 |

A marker never depended on `intake.json`, so a job with no `intake.json` beside its records still has the flag. When an
`intake.json` is there, its `private_terms.never_name` must equal the marker's or the load refuses `private_terms_stale`.

An `ip_private`-only bundle now runs no denylist, which would have written no marker and turned the `visible_text` gate
to `not_applicable`. J168 names no such hold, so `bundle.guarded` keeps the marker for a bundle that declares
`ip_private`, and an unread or opaque shown asset still waits at the operator. `private_lane` reads the declared flag,
so a deleted marker beside that `intake.json` still refuses. A bundle that declares neither flag and gives no denylist
has no hold, as on main.

`test_narrated_video_private_terms.py` and `test_narrated_video_visible_text.py` keep the old matching through their
`audit_rules` fixture for the audit. That fixture restores `MATCHED` and `SCRIPT_MATCHES` only. The `NEEDS` entry and
the two denylist conditions are not restored, and the `[NAME_ROW]` case for them was deleted, so those two rules have
no audit coverage. `test_narrated_video_j168.py` runs the shipped defaults, a name in a slide refusing at intake
included.

This change first went up as vu#85, which `654c5b08` closed. It is re-landed here on main.

vu#84 lands first, so this branch takes a signed merge of it, at `0e469d01`. Its added `shown_text_unread` cases all
sit behind a guarded intake's marker, so the marker's `never_name` can narrow every one. The merge keeps them on a
`never_name` job and refuses nothing on any other. CADE-1 swb seq 1089 asks `nv subject` to refuse wherever it knows
`never_name`, including when `intake.json` says so. The marker holds the flag, and a marker that differs from the
`intake.json` beside the records refuses `private_terms_stale`, so the marker reads what `intake.json` says. An earlier version of this note said these cases could not narrow, which was wrong:
`marker(report, ...)` receives the report, and the report holds the flag.

| Case in vu#84's `shown_texts` | `never_name` job, or a marker older than the flag | Any other job |
| --- | --- | --- |
| No guarded intake's marker | no rows, `shown_unread` lists the kinds. The worker refuses | the same, and no check reads that text |
| Intake state `partial` | `shown_text_unread` | rows of the stored source. `deliver_check` still waits at the operator |
| Marker holds no `source_sha256` | `shown_text_unread` | no rows, `shown_unread` lists the kinds |
| Stored source gone, changed or malformed | `shown_text_unread` | no rows, `shown_unread` lists the kinds |

The hand-off refusal does not cover a stored source that is gone or malformed. It runs before any intake and reads the
signed commit, so it never sees the store. That is why the merge keeps those two cases. The merge also makes
`bundle.visible_source` read `guarded`, so an `ip_private` bundle with no denylist stores its shown text.

vu#84 at `0e469d01` reads an empty JSON list, or one of only whitespace or zero-width text such as U+200B, as opaque in
both readers (CADE-1 seq 1070 and 1089). On a `never_name` job that refuses `shown_text_unread`. On any other job the
intake's `visible_text` gate holds it at the operator.

`private_terms_stale` on a digest that differs from `intake.json` stays, because it is not `shown_text_unread`.

Land order: this PR waits for cade#246 with the `shown_unread` check and for cade#267 with the hand-off narrowing. Landing it first would leave a `never_name` packet with no
refusal on one or both paths.

Measured: local, non-qualifying, targeted tests only. `test_init_from_the_intake_and_plan` fails on main and on this
branch where FFmpeg is not on PATH. Listening, demo render and application acceptance are not touched.
