# J168 removal, narrate half

November 2, 2026, TIN-7125. Direction: J168 (`9738d494`) and SPR-339 (`1786d297`). Receipts cite
R-HOOK-CONVERGENCE-20261004.

J168 removes the `ip_private` and BS-21 code refusals for go-live, and the November 30, 2026 audit revisits them. The
Cade half and the audit list are in `docs/J168_REMOVALS.md` of xoxd-ai/cade.

| Check | Site | Effect |
| --- | --- | --- |
| `ip_private` | `private_terms.required`, `read_denylist` | `ip_private` needs no denylist and no digest |
| `ip_private` | `private_terms.NEEDS` | `ip_private` needs no number or geometry entry |
| `ip_private` | `private_terms.scan`, `MATCHED` | Number and geometry entries parse and do not match |
| BS-21 | `private_terms.scan`, `SCRIPT_MATCHES` | The `script` class does not refuse |
| BS-21 | `subject.subject` | `nv subject` stops refusing `shown_text_unread` |

`never_name` keeps its denylist, its name entry and its match. `redact` still withholds a detail that holds a foreign
letter, because it refuses nothing. Restoring the rules takes `MATCHED = CLASSES`, `SCRIPT_MATCHES = True`, the
`NEEDS` entry and the two conditions, or one revert.

`nv subject` cannot see `never_name`: the packet record holds that flag, and neither the job's records nor the guarded
intake's marker carry it. `intake.json` holds it only when a guarded intake ran and the file lies beside the records,
so a job with no marker has no declaration to read. So `nv subject` drops the refusal for every job, and a job with no
marker can show a name that no check here reads. Jess's decision `654c5b08` keeps Cade's `shown-text-unread` on `never_name` packets, which
narrows the scope note `2201b219` there. BIZ-17 coverage stays, and elsewhere the removal stands.

`test_narrated_video_private_terms.py` and `test_narrated_video_visible_text.py` pin the old rules through their
`audit_rules` fixture, so their coverage stays for the audit. `test_narrated_video_j168.py` runs the shipped defaults.

This change first went up as vu#85, which `654c5b08` closed. It is re-landed here as one new commit on main. The tree
is the same but for the review fixes: the import order in `test_narrated_video_j168.py`, the `private_terms.py` module
docstring and the `never_name` text above.

vu#84 lands first, so this branch takes a signed merge of it. vu#84 adds three `shown_text_unread` cases that this
removal also reverses, because the marker holds no `never_name` either. After that merge `shown_texts` keeps the
`visible_text` rows it can read and refuses nothing:

| Case in vu#84's `shown_texts` | After the merge |
| --- | --- |
| No guarded intake's marker | No rows, as here |
| Intake state `partial` | Rows of the stored source. `deliver_check` still waits at the operator |
| Marker holds no `source_sha256` | No rows |
| Stored source gone, changed or malformed | No rows |

`private_terms_stale` on a digest that differs from `intake.json` stays, because it is not `shown_text_unread`.

Measured: local, non-qualifying, targeted tests only. `test_init_from_the_intake_and_plan` fails on main and on this
branch where FFmpeg is not on PATH. Listening, demo render and application acceptance are not touched.
