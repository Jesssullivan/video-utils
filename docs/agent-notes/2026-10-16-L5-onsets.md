## Correction to the earlier evidence

The 2026-10-15 receipt and the first TIN-5491 comment describe the segment rule as "labels outside a segment are
removed before matching; an unmatched detection inside a segment is a false positive". That rule was asymmetric.
A detection 9 ms from a label just outside a hand-drawn region edge was scored as a false positive:
`onset_agreement([1.995, 2.5], [2.004, 2.5], 0.025, [[2.0, 3.0]])` gave `false_positive_count` 1 and precision 0.5.
The same call now gives 0 false positives, precision 1.0 and recall 1.0.

## Change

- `scripts/onset_benchmark.py`
  - Detections are matched against every counted operator onset label. Recall counts only labels inside declared
    segments. A false positive is an in-segment detection that is matched to no operator label. An in-segment
    detection matched to a label outside the segment is counted as
    `detections_in_scope_matched_to_unscored_labels`.
  - `ordered_pairs` takes an optional per-label priority, used to prefer scored labels when matches are contested,
    and an optional epsilon. With the defaults it is unchanged and still agrees with the frozen `event_metrics_v2`.
  - `confirmed_only` scores confirmed labels but matches against all labels.
  - Every tolerance test adds `MATCH_EPSILON_SECONDS` (1e-9 s). With 12 labels rounded to 6 decimal places and
    detections at exactly +10 ms, recall at 10 ms was 0.1667 and is now 1.0.
  - The CLI marks an analysis whose `source_lineage.original_source_sha256` differs from the run source as
    `rejected_original_source_mismatch` and does not score it. `report_bundle.py` applies the same rule.
- `scripts/annotation_v2.py` (`import_labels`): refuses a manifest whose timeline does not declare
  `no_time_stretch: true` (`labelled_audio_requires_no_time_stretch_timeline`). This check runs before any write.
- `just/workflow.just`: `onset-import` gains `certainty` (`uncertain` by default) and `status` (`needs_review` by
  default) arguments.
- `reports/demo.qmd` section 7 treats every zero-label state as the empty state: no store, an unbound or refused
  store, and a bound store with no onset records. In each case it prints "No operator onset labels yet." with the
  store status and does not mention a scoring mode.
- Docs: `ONSET_LABELS.md` documents the edge rule with a worked example, the epsilon, the confirmed-only matching,
  the CLI lineage rule, the import flags and the no-time-stretch requirement. Each of the two skills has one
  sentence updated.
